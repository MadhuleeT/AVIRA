# Contributing to AVIRA

## Branch Workflow

- Do not work directly on the master branch.
- Create a separate branch for each feature or task.
- Use clear branch names such as:
  - frontend-login
  - backend-api
  - data-processing
  - docs-update

## Commit Guidelines

- Make small, meaningful commits.
- Use clear commit messages.
- Example:
  - Add navigation component
  - Implement iceberg data processing
  - Update project documentation

## Pull Requests

1. Push your branch to GitHub.
2. Create a Pull Request to the master branch.
3. Explain what was changed.
4. Wait for review before merging.

## Sync Before Starting Work

Always update your local master branch before starting a new task.

```bash
git switch master
git pull
